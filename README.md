# 比赛小车

普通 Python 项目，从项目根目录运行。`main.py` 读取同目录 `tasks.txt` 的 `[主线]`，按文件顺序逐条执行；启动主线时先开启常驻视觉后台，底盘与机械臂按需连接并在整趟比赛中复用。

## 运行

先查看完整动作计划，不连接设备：

```bash
python3 main.py --dry-run
```

干跑与实机读取同一份任务段落，默认选择 `[主线]`。支持空行和 `#` 注释，读到下一个段标题即结束；在任务指令处调用匹配的动作段，再回到原段继续。启动时检查当前段及所有可能调用的分支，缺段、空段、语法错误或循环调用会在连接设备之前报错；语法错误包含任务表行号。干跑用 `211` 演示任务码的含义，分别打印左、中、右三段的条件分支预览，实际位置由现场识别决定。

每个任务段落标题都自动对应一个同名命令行参数，例如：

```bash
python3 main.py --抓中间的小球
python3 main.py --抓左边的小球
python3 main.py --打中间的靶
python3 main.py --抓中间的小球 --dry-run
python3 main.py --help
```

新增 `[段落名]` 后即可使用 `python3 main.py --段落名`，无需修改 Python 代码。每次只能选择一个段落，不带段落参数时执行 `[主线]`；空段落提示“没有可执行指令”。所有段落都支持 `--dry-run`，按文件顺序执行，到下一个段标题结束。

机械臂任务段落开头应安排 `arm-calibrate`，将启动时四轴当前位置设为软件基准，并使舵机 ID1 保持固定位置；请在启动前将机械臂摆到对应 `0 0 160 24` 的初始姿态。主线在扫码姿态前建立基准；自动调用动作段时，若机械臂已经校准，段内的 `arm-calibrate` 沿用当前基准，避免在观察姿态重新置零。单独执行该段仍正常校准。纯机械臂任务不启动摄像头和 YOLO。

可用指令：`pause`、`sleep 秒数`、`straight 距离 [速度]`、`turn 角度 [半径]`、`calibrate-position`、`calibrate-ball-position`、`calibrate-object-position`、`align`、`vision-straight 距离 [速度]`、`go-ahead [停车y [速度]]`、`arm-calibrate`、`arm-disable`、`arm-move q1 q2 q3 q4`、`home` / `arm-home`、`gripper-open`、`gripper-close`、`light`、`scan-qrcode`、`detect-balls`、`detect-targets`、`小球任务`、`打靶任务`、`人质任务`、`lock-target-left [超时]`、`lock-target-middle [超时]`、`lock-target-right [超时]`。

`light` 无参数，让舵机 ID2 移到点灯角度，最多等待 1 秒；到位并停稳后立即继续，1 秒内未完成则打印提示并继续下一条指令，不中断比赛，保留舵机目标与扭矩。目标角度由 `config.py` 的 `ARM['light_angle_deg']` 配置，范围 0..360°；复用夹爪 TTL 连接，要求 `ARM['gripper_servo_id']=2`，无需先执行 `arm-calibrate`。任务表的 `[光]` 段可用 `python3 main.py --光` 单独执行，或加 `--dry-run` 预览。

`pause` 无参数，在 `tasks.txt` 需要暂停的位置单独写一行。暂停时同时检测控制台回车和夹爪舵机 ID2：按下回车，或舵机在最近 0.5 秒内向任意方向移动至少 5°，都会继续下一条指令。检测从本次暂停开始，每约 0.05 秒采样一次，忽略过期样本，并处理 0°/360° 跨界；慢速移动超过半秒才累计到 5°、小幅来回抖动都不会触发。查询起止时间用于保守判断半秒窗口，延迟回包不会被当作新发生的转动。复用机械臂 TTL 连接，只读角度，不改变舵机扭矩；需要手动拨动时可先安排 `arm-disable`。查询写入超时或应答异常时提示，并每隔至少 0.2 秒重试；恢复通信后重新建立角度基准，不跨通信缺失累计转动。设备断开等其他错误提示并保留回车通道。等待期间可按 `Ctrl+C` 取消；标准输入关闭时停止任务。干跑只打印指令、不等待或读取舵机；`pause` 自身不叠加默认步骤间隔。例如：

```text
arm-move 0 0 122.34 79.61
pause  # 检查姿态，按回车后继续
straight 0.31
```

`sleep 秒数` 在当前段落中等待指定时间后继续，例如 `sleep 0.5` 延时半秒，`sleep 2` 延时两秒。支持小数和 `sleep 0`，负数或非有限数值会在执行前报错。等待期间可按 `Ctrl+C` 取消；干跑只打印指令、不实际等待。`sleep` 自身不叠加默认步骤间隔，也不连接设备。

`scan-qrcode` 保存本趟任务码：第一位表示排爆物（小球）颜色，第二位表示反恐靶颜色，均为 1 红、2 绿、3 蓝；第三位表示救援目标形状，1 圆柱形、2 圆锥形、3 腰鼓形。例如 `211` 选择绿色小球、红色标靶和圆柱形物体。任何一位超出 `1..3`、位数不为三位或扫码超时，均停止执行后续动作。再次扫码会清除此前收集的排列。

三个任务指令均无参数，按以下规则调用 `tasks.txt` 的对应段；每次只执行选中的一段，完成后继续主线：

| 指令 | 现场位置来源 | 调用的动作段 |
| --- | --- | --- |
| `小球任务` | `detect-balls` 收集的颜色排列，匹配第一位 | `[抓左边的小球]`、`[抓中间的小球]`、`[抓右边的小球]` |
| `打靶任务` | `detect-targets` 收集的颜色排列，匹配第二位 | `[打左边的靶]`、`[打中间的靶]`、`[打右边的靶]` |
| `人质任务` | 校准后调用 `vision.observe_target("object", 形状)`，匹配第三位 | `[抓左边的物体]`、`[抓中间的物体]`、`[抓右边的物体]` |

颜色按现场位置匹配，不按二维码数字直接决定左、中、右。例如扫到 `211`，球从左到右为蓝、绿、红，靶为红、蓝、绿，圆柱形物体位于右边，就执行 `[抓中间的小球]`、`[打左边的靶]`、`[抓右边的物体]`。未扫码、未收集对应排列、颜色缺失或重复、救援位置不明确时停止任务。颜色排列保存在本次运行内存中；打靶分支使用当前识别返回值选择段落，并将二维码指定颜色传给锁靶控制，避免画面中心变化后选错颜色。

`detect-balls` 调用 `tasks/detect_ball.py`，复用后台 YOLO 物体模型的小球识别结果。按三个球的检测框中心从左到右排序为左、中、右，颜色直接读取模型类别（红、绿、蓝）。等待三个球完整可见且顺序连续稳定后，逐个打印，例如 `小球位置：左，颜色：红色`；缺球或位置重叠会继续等待，超时后停止。当前 `[主线]` 段已在机械臂到达观察姿态后加入该指令，并将返回排列用于 `小球任务`。干跑仅打印检测步骤。

`detect-targets` 无参数，调用 `tasks/detect_target.py`，复用项目物体 YOLO 模型中的 `red_target`、`green_target`、`blue_target` 标靶识别结果。与小球观察相同，按检测框中心横坐标排序，等待三个标靶完整可见且顺序连续稳定后，打印并记录左、中、右的颜色、检测框和中心像素坐标；该指令不移动底盘或机械臂。每次成功将结果按左、中、右顺序保存到 `tasks/target_positions.json` 的 `targets` 列表，覆盖上次成功记录；缺靶、同色重复或位置重叠会继续等待，超时或取消时不覆盖已有记录。坐标以当前画面左上角为原点，向右、向下为正，单位 px。

`tasks.txt` 的 `[主线]` 已加入 `detect-targets`。实机执行到该指令时，应确保机械臂处于能看全三个标靶的观察姿态；其他任务段同样可在观察姿态之后添加此指令。干跑不生成位置文件，实机记录不加入 Git。

`[打左边的靶]`、`[打中间的靶]`、`[打右边的靶]` 分别使用 `lock-target-left`、`lock-target-middle`、`lock-target-right`，调用 `tasks/lock_target.py` 的 PID 瞄准控制。先等待红、绿、蓝三个标靶各出现一次，左右顺序一致且中心位置连续稳定，默认确认 3 个有效新帧，再开始瞄准。单独执行这些段时，按横坐标排序选择左、中、右标靶；由 `打靶任务` 自动调用时，首次选择按二维码指定颜色。锁定后按颜色和邻近位置跟踪同一标靶；选中目标丢失或画面无效时，四轴下发 `arm-move -90 0 160 4` 复位指令，随后使用新画面重新确认三个标靶并继续瞄准原颜色。复用机械臂 RS485 与视觉摄像头，ID2 在瞄准期间保持固定角度、ID1/ID4 跟踪，启动校正网页并读取已保存的瞄准点；纯锁靶段只启用物体 YOLO，主线已加载时复用实例。已有校准时沿用原零点；独立运行且无配置零点时，启动前须将机械臂摆到 `-90 0 160 4`，程序只读取并记录该观察姿态的编码器角度，不重新校准。

运行 `python3 main.py --打左边的靶`（中、右替换对应段名）；加 `--dry-run` 只打印控制步骤，不连接设备或开启网页。三个锁靶任务均在横向、纵向误差绝对值分别 ≤ 8 px 且连续保持 2 秒时完成，保留位置保持并继续执行当前段内的下一条指令。计时使用连续有效新帧的采集时间；缺靶、重复或过期画面、误差超限、画面间隔超过新鲜度上限及瞄准点变化均重新计时。完成容差与 PID 的 `tolerance_px` 参数独立。可在任务表写 `lock-target-left 10` 设置最长等待 10 秒，超时仍未到位则停止任务，不执行后续指令；省略或写 0 表示不限等待时间。按 `Ctrl+C` 取消时失能机械臂 ID1–4。当前接入的是已有瞄准控制，发射动作尚未实现。

`calibrate-ball-position` 无参数，已放在 `[主线]` 段的 `detect-balls` 后、`小球任务` 前。按三个球的检测框中心横坐标取中间球，以同一帧原图宽度的一半作为屏幕中心线；中间球偏左就后退，偏右就前进。每个有效视觉新帧将横向误差乘以 `mm_per_px` 换算成前后位移，再加上图像采集时刻的编码器里程，生成目标位置。控制器保存近期里程并插值匹配采集时间，补偿图像推理延迟；目标位置在两个视觉新帧之间保持不变。

100 Hz 底盘控制环使用“目标位置 − 编码器当前位置”的毫米误差更新位置 PID，输出前后目标速度；左右里程差 PID 保持直行，主机轮速 PI 修正速度，再传给驱动板自身的速度 PID。驱动板已有积分，主机轮速环默认 `speed_kp=0.6, speed_ki=0`，避免叠加积分；减速、换向和制动都会清除旧积分。测速使用累计编码器的 80 ms 窗口，独立检查 10 ms 增量反馈是否断流。

电机实测发现小速度指令会长时间不动、零速停车也有滞后，因此位置容差之外设置 35 mm/s 起步速度下限，并按实测轮速和 `brake_tau=0.04 s` 提前制动。运动期间限制加速度，制动时直接取消运动指令；实测速达到 20 mm/s 时调用反向 PWM 制动，低于该速度使用零速度闭环锁轮。制动后等停稳，再根据停车后的新帧决定是否补偿剩余误差。球心在 ±8 px 内连续确认 3 个新帧、位置误差在 ±2 mm 内、轮速低于 5 mm/s、0.2 s 内左右里程漂移各不超过 0.25 mm，且有停车后采集的新帧，才完成校准。日志显示目标/当前位置、位置误差、目标速度、轮速指令、实测轮速及运动/制动/停稳状态。

小球校准采用多帧缺失监测：漏检 1–2 个新帧时保持最近的有效编码器目标，不把旧图像误差逐拍累加；连续缺失 `missing_frames=3` 帧或最近有效画面过期（默认 0.6 s，包含推理延迟）时先暂停运动、清除旧目标，并等待识别恢复。暂停后需连续 `recovery_frames=2` 个新帧完整识别三个球，再更新目标并继续校准；重复、过期和乱序画面不能增加确认次数。持续 `lost_timeout=2.0` s 无有效完整画面才终止比赛，短暂漏检不会直接终止。漏检会清除到位确认计数，缺球画面不能完成校准。编码器断流、中间球颜色变化、超时或取消仍会停止任务。参数在 `config.py` 的 `BALL_POSITION` 中调整；物品校准仍沿用单帧缺失暂停、单帧恢复和 0.6 s 断流终止。

换算比例、位置 PID 增益、最大速度（默认 100 mm/s）、加速度、两种容差、稳定帧数、累计移动上限（默认 0.3 m）和超时（默认 30 s）在 `config.py` 的 `BALL_POSITION` 调整。当前依据现场估计“110 px 约对应 40 mm”，设 `mm_per_px=40/110≈0.3636`；这不是实测标定值，后续可在实际观察姿态、拍摄距离和分辨率下修正：`mm_per_px = 前后移动距离(mm) / 球心横坐标变化绝对值(px)`。`kp` 单位为 1/s，`ki` 为 1/s²，`kd` 无量纲，`derivative_tau` 是微分滤波时间常数（s）。当前位置环默认只启用 P（`kp=0.6`，`ki=kd=0`）；110 px 偏差约生成 40 mm 的位置修正，比例输出 24 mm/s 经起步下限提高至 35 mm/s。干跑会显示串级结构、换算比例和位置 PID 参数。原 `calibrate-position` 仍是 IMU 撞击检测的倒车靠坎。

仅电机测试可运行 `python3 -m debug.ball_motor_check --port /dev/ttyUSB0 --distance-mm 20`：只打开明确指定的电机串口，使用真实编码器构造模拟视觉目标；单次目标限制在 ±30 mm，累计移动保护 45 mm，超时 12 s，退出保留零速闭环。测试不连接摄像头、IMU 或机械臂，不能替代真实球识别和像素比例的验证。结果默认保存在 `/tmp/ball_motor_check.json`，可通过 `--output` 指定位置。

动作均需在执行的任务段落中明确列出，包括机械臂校准；使用 `arm-move` 或回位前应先安排 `arm-calibrate`。`arm-disable` 无参数，调用 `arm.disable()` 让机械臂四轴电机 ID1–4、工具旋转舵机 ID1 和夹爪舵机 ID2 全部失能（夹爪 ID 由 `ARM['gripper_servo_id']` 配置）。无需先校准，按需连接 RS485 与 TTL 两条总线，已建立的软件零点仍保留。某个设备失能失败时仍尝试其余设备，随后报错并停止任务。后续 `arm-move` / `home` 重新使能四轴，`gripper-open` / `gripper-close` 重新使能夹爪，`arm-calibrate` 重新使工具舵机保持配置位置。

运行依赖列在 `requirements.txt`，已验证 Python 3.12 和 Ultralytics 8.4.164。安装依赖时保留本机已匹配的 OpenCV、PyTorch、torchvision 和 CUDA 环境。

在 `config.py` 填写串口、摄像头和推理设备，再执行比赛：

```bash
python3 main.py
```

电机和 IMU 端口留空会自动识别；机械臂默认使用固定设备路径；夹爪留空会读取舵机并复用 `arm/servo_binding.json` 绑定。实机建议填写固定端口。两套 YOLO 推理默认使用 `cuda:0` 和 FP16，需要可用的 CUDA 环境。

底盘串口单次写入最长等待时间由 `BASE['write_timeout']` 配置，默认 1.0 秒，原先固定为 0.2 秒。`Write timeout` 表示主机串口写操作超时，与 `BASE['turn_timeout']` 的整段转弯超时不同，也不是等待驱动板应答（轮速指令无回复）。报错包含端口、写入上限和指令；写入超时仍停止任务，不自动重发可能部分写入的运动指令。正常写入完成后立即继续，延长上限不会每帧固定等待 1 秒；编码器／IMU 数据过期检查继续生效。反复发生时需检查 USB／串口连接和主机负载，单纯延长上限不能保证解决通信故障。

机械臂 RS485 分开配置发送和应答等待：`ARM['serial_write_timeout']=1.0` 秒限制单次写入（原为 0.1 秒），`ARM['serial_timeout']=0.1` 秒限制发送完成后的应答等待。写入超时会显示串口、写入上限、耗时和帧长。只读状态查询 `0x0B` 在写入超时或应答异常时最多尝试 3 次，每次使用新序号过滤迟到回复；设备断开等传输错误立即停止。移动指令不会自动重发，避免重复启动运动。正常发送立即继续，延长上限不会每次固定等待 1 秒。反复发生写入超时仍需检查 USB／RS485 连接、供电和主机负载。

舵机 TTL 同样分开配置：`ARM['gripper_write_timeout']=1.0` 秒限制串口写入，`ARM['gripper_timeout']=0.1` 秒限制应答等待。独立舵机驱动和自动探测的默认写入上限为 `SERVO['write_timeout']=1.0`。查询报错包含真实串口、波特率、目标 ID、指令、写入上限和耗时；收到的数据先从缓冲区读取，避免视觉后台初始化造成线程调度延迟时，已有回包仍被判成超时。正常通信立即返回，不固定等待 1 秒；只有 `pause` 的只读查询会在失败后继续尝试，舵机运动与扭矩指令不自动重发。

机械臂 RS485 波特率为 921600，`ARM['serial_latency_ms']=1`。Linux FTDI 驱动的接收延时默认是 16 ms，普通用户通常无权修改；本机已安装 `udev/99-car-arm-latency.rules`，将机械臂适配器 `FTBVQPDL` 的接口 `00` 永久设为 1 ms，重启或 USB 重连后自动生效。换机部署时，从项目根目录安装：

```bash
sudo install -o root -g root -m 0644 udev/99-car-arm-latency.rules /etc/udev/rules.d/99-car-arm-latency.rules
sudo udevadm control --reload-rules
sudo udevadm trigger --action=change --subsystem-match=usb-serial
sudo udevadm settle
```

规则按设备序列号和接口匹配，不依赖 `ttyUSB` 编号；更换适配器后需同步修改规则和 `ARM['port']`。可运行 `cat /sys/bus/usb-serial/devices/$(basename "$(readlink -f /dev/serial/by-id/usb-FTDI_USB__-__Serial_Converter_FTBVQPDL-if00-port0)")/latency_timer` 确认输出为 `1`。这项设置降低 USB 接收缓冲等待，电机端与主机波特率仍需保持一致。

`calibrate-object-position` 无参数，用于后续物品区。复用后台 YOLO 的圆柱、圆锥、腰鼓检测，忽略小球；三个物品完整可见时按检测框中心横坐标排序，取中间那个对齐到同一帧原图宽度的一半。中间物品偏左后退、偏右前进，复用小球的编码器位置 PID、延迟补偿、制动和停稳确认；缺物品立即停车，中间物品形状变化、视觉或编码器断流、超时及取消均停止任务。返回结果中的 `shape` 是中间物品的形状。

在 `tasks.txt` 对应任务段中，先安排物品区的机械臂观察姿态，再写 `calibrate-object-position`，校准成功后继续回位或抓取。无需先执行 `detect-balls`。当前 `[主线]` 已安排观察姿态和该校准指令，随后由 `人质任务` 选择并执行指定形状的抓取段。`config.py` 的 `OBJECT_POSITION` 独立配置速度、容差、PID 和超时，初值沿用小球参数；`mm_per_px` 需按实际物品观察姿态、拍摄距离和分辨率重新标定。干跑打印参数，不连接设备。

距离单位 m，底盘速度 mm/s，角度单位度，动作间隔 0.5 秒。普通直走支持负距离，视觉直走只接受正距离。移动控制已去掉额外的到位验收：普通直走和视觉直走结束后不再按距离误差判失败，转弯结束后不再按角度或半径误差判失败；实测数据仍用于控制和日志。距离、转角减速停车，以及通信、反馈断流、控制超时和取消处理继续生效。视觉对正和直走的航向环增益共用 `VISION_CONTROL`，`ALIGN` 配置对正参考、速度和停车条件。

普通直走和视觉直走共用 `config.py` 的 `BASE['speed']`（mm/s）；倒车靠坎 `calibrate-position` 独立使用 `POSITION['speed']`（mm/s，填写正数，程序处理倒车方向）。可分别修改，例如 `BASE['speed']=300.0`、`POSITION['speed']=200.0` 表示直走 300 mm/s、倒车校准 200 mm/s。修改后重启程序生效，干跑显示对应动作的速度。任务表中的 `calibrate-position` 仍无需参数。

`calibrate-position` 检测到撞击后先停车，再给底盘四轮发送零 PWM，解除速度闭环保持并释放驱动力。等待下一步和退出程序时继续保持失能；下一条移动指令自动恢复驱动。校准失败或取消时也尝试停车和释放，通信失败会报告错误。

加减速参数在 `config.py`：普通直走和视觉直走共用 `STRAIGHT['ACCEL']=600.0` mm/s²、`KP_POS=4.0` s⁻¹；转弯使用 `TURN['ACCEL']=0.6` m/s²、`ANGULAR_ACCEL=6.0` rad/s²、`ANGLE_KP=3.0` s⁻¹。提高加速度限值会缩短参考速度的变化过程，提高位置／转角增益会让车辆更晚开始降速、缩短低速收尾。当前这五项为原参数的两倍，直走和转弯巡航速度由 `BASE` 配置，倒车校准速度由 `POSITION` 配置。`calibrate-position` 默认也使用直走加速度。制动提前时间用于补偿实车停车响应，应根据停车后的距离／角度误差实测调整；仿真耗时不能代表实车耗时。

`vision-straight 距离 [速度]` 的距离单位为米，可选速度单位为 mm/s，范围为 `(0, 1000]`。例如 `vision-straight 1 600` 以 600 mm/s 为巡航目标前进 1 米；省略速度时使用 `BASE['speed']`，指定速度只影响当前指令。起步仍按加速度限制提速，临近终点按剩余距离减速停车，视觉纠偏时左右轮速会有所不同。干跑打印当前指令采用的速度。

`go-ahead [停车y [速度]]` 不指定距离，沿用视觉直走的巡线、横向补偿、航向与轮速控制，持续前进直到跑道尽头。第一个参数为原图停车行（px），例如 `go-ahead 300` 在确认的端点达到或越过 `y=300` 时下发零轮速，等待车轮停稳后结束指令；省略参数时使用 `config.py` 的 `BASE['go_ahead_stop_y']`，默认 292。停车行必须在 `[0, VISION['height'])` 内。可追加第二个参数指定速度，例如 `go-ahead 300 200` 使用 200 mm/s；原来的单参数速度写法改为先写停车行再写速度。通过 `vision/runway_endpoint.py` 的 `EndpointDetector` 检测共用摄像头的新原始画面。端点还未出现时继续前进，重复帧、过期帧及尚未确认的跳变不触发完成；摄像头断开或持续没有新鲜画面会停车并终止任务。省略速度时使用 `config.py` 的 `BASE['go_ahead_speed']`，默认 300 mm/s；与普通直走和 `vision-straight` 的速度分别调节。显式参数只覆盖当前指令，不修改配置；可选速度范围为 `(0, 1000]` mm/s，不按距离切换末段 gap。日志保存到 `VISION_CONTROL['LOG_DIR']`，文件名以 `go-ahead_` 开头。`tasks.txt` 已提供 `[跑道尽头]` 段，可用 `python3 main.py --跑道尽头 --dry-run` 预览，`python3 main.py --跑道尽头` 实机执行。

有可用边界且通过当前帧长度过滤时使用视觉巡线，包括短距离和临近终点的运动。左右边界平均得到跑道中心线，在 `VISION_CONTROL['LOOKAHEAD']` 指定的画面高度比例处（当前 `0.7`，夹在有效边界范围内）取前视点；既修正车头方向，也修正车身横向偏移。出发时已有的偏移同样参与纠偏。内环默认用编码器 gap 估算角速度。

行驶中视觉过期（`VISION_CONTROL['LOST_STOP']=0.6` s）或拿不到可用中心线时，切换 gap 盲走：以切换时的左右轮累计里程差为基准，使用编码器航向环保持当时车头方向，继续按剩余距离减速并在目标位置停车。进入盲走时清除旧视觉滤波和航向环积分，不继续使用过期图像转向。后台视觉仍被监测，连续 `GAP_RECOVERY_FRAMES=2` 个有效新帧后恢复视觉纠偏；重复、过期、乱序和缺边界的新帧不能凑足连续确认。可以多次丢失并恢复，每次丢失都会重新锁定当前 gap。CSV 的 `src=gap-blind` 表示临时盲走，此时画面几何列留空。盲走只能保持航向，不能矫正横向位置或执行摄像头横向偏移补偿；视觉恢复后继续纠偏。编码器断流、总时长超时、过大航向误差和取消仍会停车。出发前仍等待可用跑道中心线；`align` 的视觉丢失处理沿用原规则。

`VISION_CONTROL['LANE_WIDTH_MM']=300.0` 表示左右边界实际间距 30cm；`LATERAL_OFFSET_MM` 表示相对原来画面居中路线的车身横移补偿，当前 `10.0` 是向左 1cm，设为 `50.0` 是向左 5cm。正值向左、负值向右，设为 `0` 恢复画面居中。每帧在同一前视行测量边界像素间距，按 `像素补偿 = 像素路宽 × LATERAL_OFFSET_MM / LANE_WIDTH_MM` 换算；车往左时中线在画面里往右，所以参考横坐标为画幅中心加像素补偿。控制持续跟踪这条偏移后的路线。单侧边界短暂缺失时沿用最近两侧都在时测得的宽度；没有可用宽度则切换 gap 盲走。这项补偿用于 `vision-straight` 和 `go-ahead`，`align` 仍使用原参考。补偿需要数值 `LOOKAHEAD`；`LOOKAHEAD='vanishing'` 只修正航向，须将 `LATERAL_OFFSET_MM` 设为 `0`。

`vision-straight` 与 `go-ahead` 共用 `VISION_CONTROL['MIN_BOUNDARY_LENGTH_PX']=60.0`：只要本帧任一实际识别到的边界线段短于 60 原图像素，就跳过整帧视觉纠偏。长度为实际近、远端点之间的欧氏距离 `sqrt((Δx)²+(Δy)²)`，恰好 60px 可以使用，与边界在画面中的 y 位置无关。即使另一侧足够长，也不使用该帧；重读这张短边界画面不能沿用旧视觉误差。跳过期间清除旧视觉滤波和航向环积分，以切换时的左右轮里程差为基准，用 gap 保持当时航向；下一张长度合格且中心线可用的新帧立即恢复纠偏。真正的视觉过期或缺失仍需按 `GAP_RECOVERY_FRAMES` 确认恢复，短边界帧不能增加确认计数。CSV 的 `src=gap-short` 表示仅因短边界跳过画面，返回的 `short_frames` 为被跳过的新帧数；参数设为 `0` 可关闭长度过滤。`vision-straight` 继续按编码器目标距离减速停车，`go-ahead` 继续识别跑道尽头并在端点达到指令指定的停车行（未指定时默认 `y=292`）时停车；编码器或摄像头断流处理继续生效。`align` 沿用自身的视觉处理规则。

可选的旧距离阈值 `VISION_CONTROL['GAP_FINISH_MM']` 保持默认 `0`，不按剩余距离关闭纠偏。设为正值时，`vision-straight` 也会在剩余距离小于等于该值（mm）时锁定当前 gap；总距离不超过该值时全程使用 gap，无需视觉就绪。该距离条件不适用于 `go-ahead`。位置环、轮速环和编码器断流停车继续生效。

每次执行 `vision-straight` 默认在 `logs/vision-straight/` 保存独立 CSV，运行时打印路径；`VISION_CONTROL['LOG_DIR']=None` 可关闭保存。起步即打印前视行、中心线像素偏移、像素补偿、原始误差、差动修正和左右轮速度指令，行驶中继续打印指令与实测轮速。CSV 包含 `lat_px`（前视点相对画幅中心的原始偏移）、`target_x`（补偿后的参考横坐标）、`offset_px`（本帧像素补偿）、`e_raw_deg`（补偿后误差）、`trim_mms`、`cmd_l/cmd_r`（主机下发的速度，驱动层还会限幅取整）、`v_l/v_r`（编码器实测速度）和 `gap_mm`。到达补偿后的路线时，`lat_px` 应接近 `offset_px`，原始误差接近零。若左右轮指令不同但实测轮速长期相同，检查驱动执行、轮序和底盘响应。这些日志用于区分实车问题，仿真通过不能代替实车验证。

二维码必须为三位 `1..3`：第一位选排爆物颜色，第二位选反恐靶颜色（1 红、2 绿、3 蓝），第三位选救援目标形状（1 圆柱形、2 圆锥形、3 腰鼓形）。目标识别要求三个候选完整、目标唯一、连续稳定，否则超时并停止。

任务表的 `arm-calibrate` 读取四轴当前位置作为软件基准，并复用夹爪 TTL 串口给工具舵机 ID1 下发固定角度、使能扭矩。角度在 `config.py` 的 `SERVO['fixed_angles_deg'][1]` 设置，单位为度，与 `debug/angles.py` 的舵机角度一致；例如 `164.0` 表示 164°，自动换算为编码器位置 1866。原 `fixed_positions` 配置已改为 `fixed_angles_deg`，无需手动换算编码器值。初始化必须确认 ID1 到位并连续停稳后才打印校准成功；超时、过载、通信错误或等待期间取消时，尝试失能 ID1 并停止任务，保留夹爪 ID2 的状态。到位超时、容差和停稳时间使用 `SERVO` 的 `move_timeout`、`arrival_tolerance`、`settle_seconds`。正常退出保留 ID1 的扭矩与目标，显式 `arm-disable` 则关闭工具舵机和夹爪的扭矩。单独调用 `arm.calibrate()` 和角度调试仍只建立软件基准；需要同时固定 ID1 时调用 `arm.calibrate(hold_tool=True)`。初始逻辑角为 `0 0 160 24`；`home()` 等待回到本次初始姿态并连续到位。夹爪 ID2 的张开、闭合角度分别在 `ARM['gripper_open_angle_deg']`、`ARM['gripper_close_angle_deg']` 设置，夹持时等待到位或实际朝目标运动后停稳，退出不自动松开物体。

任务表的 `arm-move`、`arm-home`、`home` 默认阻塞执行：四轴编码器误差均在 ±5° 内，并连续保持 0.2 秒才执行下一条指令；单次运动最多等待 30 秒。默认角度容差恢复旧版的 5°，允许例如 ID2 目标 0°、实际 −3.03° 时继续任务；该设置只改变完成判定，不消除实际位置偏差。如需更高精度，可降低 `ARM['arrival_tolerance_deg']`，但超出容差的偏差仍会导致超时。`ARM['arrival_speed_rpm']` 默认为 `None`，不以速度反馈作为完成门槛，避免已经到位却因位置保持时的非零速度反馈一直等待；如需同时检查转速，可设为正数，例如 `0.5` 表示各轴转速绝对值均须 ≤0.5 rpm。连续角度到位不代表瞬时速度必为零，运动完成后电机仍保持位置目标。超时报告各轴目标、实际角度、速度和当前到位条件并尝试失能四轴，任务不会继续。参数在 `ARM` 的 `arrival_tolerance_deg`、`arrival_speed_rpm`、`arrival_settle_seconds`、`move_timeout` 调整。自动调用的抓物体段继续沿用主线零点。任务间隔由 `STEP_GAP` 配置。

`gripper-open` 等待张开到位并停稳；`gripper-close` 等待闭合到位，或已观察到运动后在被夹物体处停稳，保持扭矩后再继续抬臂。后一条件只确认夹爪停止运动，不能证明抓到了物体。夹爪最多等待 8 秒、位置容差 6 个编码器计数、停稳 0.2 秒，在 `SERVO` 的 `move_timeout`、`arrival_tolerance`、`settle_seconds` 调整。显式 `wait=False` 的低层指令仍可立即返回；锁靶跟踪和丢靶复位仍使用原有直接下发方式。`plane-first`、`base-first` 阻塞时会等前段到位再开始后段。

机械臂四轴已去掉软件角度限位，目标角度只检查有限数值及串口协议整数范围。舵机 ID1 的固定位置仅是校准动作的目标，后续允许下发其他绝对位置或相对旋转；`hold()` 保持当前角度。STS 驱动仍使用单圈位置模式，绝对目标范围为 0..4095（0..360°）；相对角度只换算最终单圈目标，不表示实际执行多圈运动。

编码器比例为 `0.00016029 m/count`；普通直走和视觉控制轮距为 190 mm；圆弧轮距为 0.41 m，换算为 `6379 count/m`。这些现场标定值独立保留。

`turn 角度 0` 原地转向接近目标时，轮速参考最低保持 50 mm/s，仍按角加速度限制起步；停车窗口为剩余 1° 加实测角速度 × 0.04 s，进入制动后停稳 0.25 s 再执行后续指令。参数在 `TURN` 的 `SPIN_MIN_WHEEL_SPEED`（m/s）、`SPIN_STOP_ANGLE_DEG` 和 `SPIN_BRAKE_LEAD_SECONDS` 调整。50 mm/s 和 0.04 s 是初始值，需要实车确认：若收尾转不动，小幅提高最低轮速；若过转，提高制动提前时间；若提前停得太多，降低提前时间。圆弧轮速不应用此下限。持续非零指令下四轮编码器 1.5 s 不变仍停止任务，报错包含已转角度、剩余角度和四轮指令。

每次转弯默认在 `logs/turn/` 保存控制 CSV，结束时打印实测转角；`TURN['LOG_DIR']=None` 可关闭保存。日志中的 `yaw` 为已转角度（°），`cmd1..cmd4` 为下发轮速（mm/s），`count1..count4` 为编码器计数，`phase=brake` 表示已进入制动；结合这些列可以区分收尾停住、驱动不执行和反馈断流。

主任务、摄像头采集、视觉推理分别在线程中运行。主线启动时调用 `vision.start()`，后台打开摄像头并加载边界、物体两套 YOLO 模型；加载期间主线程可继续执行其他动作。模型和摄像头整趟常驻，重复调用或切换模型开关都复用实例，不重新加载权重。边界和物体持续在后台推理，只保存最新完成帧；彩色靶在观察请求期间由同一后台线程识别。

物体 YOLO 在输出结果前，先过滤无效检测，再按置信度从高到低去除重叠框，不区分类别。候选框与已保留框只要有面积交集，就丢弃该候选；仅边缘接触或完全分离的框保留，置信度相同时保留模型先返回的框。网页画框、小球、物品和标靶任务共用这份筛选后的结果。

主任务仍直接调用 `vision.observe_target(kind, value)`、`vision.scan_qrcode()` 或将同一个 `vision` 传给底盘视觉动作。目标观察读取后台结果，等待调用之后的新画面连续稳定，不在主线程重新执行 YOLO。首次调用若模型尚未加载完，最多等待 `VISION['model_wait']` 秒，再按 `observe_timeout` 等待目标；视觉行驶按原逻辑等待新鲜边界。扫码临时暂停 YOLO、切换分辨率，结束后恢复推理，模型仍保留。独立使用 `Vision` 时可先调用 `start()` 提前加载，并在退出时调用 `close()`；`main.py` 已自动处理。

编码器和 IMU 也在后台采集。重复或过期反馈不能延长有效期，编码器增量仅消费一次，编码器反馈丢失会停车；视觉丢失时，视觉直走切换 gap 盲走，其他动作按各自的暂停/停车规则处理。主程序结束时，底盘保留当前停车状态：速度模式发送零速度保持闭环，已零 PWM 释放则继续保持释放；机械臂保留使能和最后位置目标，随后关闭设备连接、等待视觉线程退出。退出清理不额外失能机械臂。动作内部遇到错误或取消时，原有停车、失能保护仍生效。清理错误不会覆盖原始异常。

## 待填写动作

`tasks.txt` 已提供小球、标靶和物体各三个位置的动作段，主线按扫码目标及现场排列调用。保留的独立任务函数中只有中间小球动作已实现。左/右小球、三个位置的靶和物体共 8 个分支调用时会抛出 `NotImplementedError`。`main.py` 默认执行 `[主线]`，支持用 `--段落名` 单独执行任务表的对应段落，直接读取该段落的指令；三个任务指令也调用任务表动作段。

主线顺序和数值由 `tasks.txt` 决定；测试验证段落边界、指令顺序和异常清理。中间小球独立函数的 7 步动作仍由 `tests/fixtures/mission_actions.json` 验证。

## 调试与验证

独立调试时关闭比赛主线，避免争用设备：

```bash
python3 -m debug.camera_web --port 8080
python3 -m debug.angles --hz 5
python3 -m debug.angles --hz 5 --duration 10 --json
python3 tasks/detect_ball.py
python3 tasks/lock_target.py
python3 vision/runway_endpoint.py
bash tests/run.sh -q
```

`python3 vision/runway_endpoint.py` 独立识别跑道端点，并将带标记的监视画面推流到 `0.0.0.0:8081`。同一局域网浏览器访问终端打印的地址；本机访问 `http://127.0.0.1:8081`。也支持 `python3 -m vision.runway_endpoint` 和从其他目录运行脚本绝对路径。程序共用项目的摄像头采集和 MJPEG 推流协议，不加载 YOLO。

每帧只取中心一列 `x=宽度//2`，从下往上比较上下各 8 个像素的 Lab 均值，同时检查色度差、黄色分量增加和上窗口的黄色像素占比。遇到第一个合格的灰→黄突变立即停止搜索，不标记更高处的突变；标记位置是比较窗口的分界行，受窗口大小影响可能相对实际边缘偏移数个像素。单纯亮暗阴影和孤立噪点不会作为灰→黄端点。

首次连续 3 个新帧在首个候选 ±6 px 内才显示端点；正常移动使用指数平滑，超过 40 px 的跳变先截住并保留旧点，连续 5 个新帧确认同一新位置才切换。缺失、重复、乱序、过期、取帧超时或候选漂移超限会打断连续确认。连续缺失 10 帧，或旧点超过 `VISION['frame_stale']`（默认 0.6 s）没有重新匹配，清除旧点并重新确认。网页绿色圆圈表示当前稳定端点，橙色圆圈表示暂时保留的旧点；每帧最多标记一个点。坐标原点在左上角，`y` 向下增加。

默认参数在 `config.py` 的 `RUNWAY_ENDPOINT`，均可通过命令行覆盖，例如 `python3 vision/runway_endpoint.py --color-threshold 6 --yellow-threshold 4 --max-jump-px 40 --jump-frames 5 --port 8081`；`--window`、`--stable-frames`、`--stable-tolerance-px`、`--smoothing`、`--lost-frames` 调整降噪与防抖。像素参数按实际分辨率计，默认值针对 1280×720。`--camera 0` 指定摄像头，`--hz 20` 限制最高识别及推流频率，`--duration 10` 运行 10 秒后退出。监视接口包括 `/stream.mjpg`、`/frame.jpg` 和 `/api/status`，多个浏览器共享一次识别与 JPEG 编码；按 `Ctrl+C` 或收到 `SIGTERM` 时关闭输入与网页。

已有摄像头调试程序运行时，可以读取其原始推流，避免重复打开设备：`python3 vision/runway_endpoint.py --stream-url http://127.0.0.1:8080/stream.mjpg --port 8081`。请在原调试网页关闭模型开关，保证输入不含检测标记。网络输入后台只保留最新接收帧；其新鲜度按本机接收时间判断，远端摄像头的真实采集延迟由上游负责。

`python3 tasks/detect_ball.py` 独立打开摄像头，只加载物体 YOLO 模型，默认推理完成立即打印并读取下一帧。终端显示模型路径与类别、每帧识别类别、置信度、中心坐标、小球数量、推理耗时和帧龄；三个球可排序时打印左、中、右颜色，缺球时持续显示当前结果。调试入口立即打印，不等待主线的连续稳定确认。按 `Ctrl+C` 退出并关闭摄像头。支持 `--camera 0`、`--device cpu`、`--conf 0.15`、`--once`；显式传入 `--hz 5` 可限制最高频率，`--image screenshots/图片.jpg` 可用已有图片检测一次。也可通过 `python3 -m tasks.detect_ball` 启动。

`python3 tasks/lock_target.py` 独立打开摄像头和机械臂 RS485，加载项目 `vision/models/objects/weights.pt`，使用 YOLO 的 `red_target`、`green_target`、`blue_target` 类别及原图检测框识别三色标靶。无配置零点时，启动前将机械臂摆到 `-90 0 160 4`，程序记录此观察姿态用于丢靶复位。等待三色标靶各唯一出现且连续稳定后，无参数时选择横向中间的标靶；可传 `left`、`middle`、`right` 选择初始位置，或 `red`、`green`、`blue` 指定颜色，例如 `python3 tasks/lock_target.py red`。首次锁定后按颜色和邻近位置跟踪同一目标，不随左右顺序变化重新选靶；跟踪期间只需选中靶可见。目标丢失时四轴下发观察姿态复位指令，暂停 PID，随后重新等待三个靶稳定出现；保留原目标颜色并清除旧画面位置，避免复位后的画面位移妨碍重获目标。

横向误差驱动 ID1：目标在瞄准点左侧减角，右侧增角；纵向误差驱动 ID4：目标在瞄准点上方减角，下方增角。未校正时瞄准点为画面中心。两轴各用独立 PID，误差按画面半宽/半高归一化，输出角速度（°/s），再乘新帧时间间隔生成角度增量；每次目标角基于当前编码器反馈，并按编码器精度（约 0.022°）量化，避免小修正被协议截成零。容差由 `tolerance_px` 设置，最大角速度 150°/s（25 rpm）、单次增量最多 10°，进入容差后保持该轴当前角度。速度上限只限制 PID 输出，提高上限不会自动放大 PID 算出的速度。PID 带微分滤波、积分抗饱和，缺靶或画面过期时清除 PID 历史。三个标靶稳定确认后，机械臂电机 ID2 移至 12° 并由位置环持续保持，速度读取机械臂配置；固定角度由 `TARGET_LOCK['motor2_angle_deg']` 配置。ID1、ID4 负责标靶跟踪，ID3 在跟踪期间保持原状。PID 角度直接使用多圈编码器角；复位使用已有零点、关节方向和偏置换算任务表中的关节角。

参数在 `config.py` 的 `TARGET_LOCK` 中调整，也可使用 `--kp 30 --ki 0 --kd 0.3 --hz 20 --tolerance-px 8 --max-rate-deg-s 150 --max-step-deg 10` 临时覆盖。稳定确认帧数由 `stable_frames` 设置（默认 3），中心相对本轮首帧的允许漂移由 `stable_distance_ratio` 设置（默认 0.03，按画面宽、高归一化）；可用 `--stable-frames 5 --stable-distance-ratio 0.02` 临时覆盖。缺靶、重复或过期帧、颜色重复、排列变化和位置漂移超限均重新确认。YOLO 推理设备读取 `VISION['infer_device']`，可用 `--device cpu` 或 `--device cuda:0` 覆盖；置信度默认读取模型配置，可用 `--conf 0.4` 覆盖。摄像头和机械臂串口支持 `--camera 0 --port /dev/ttyUSB0`；`--duration 10` 运行 10 秒后退出。丢靶复位命令每次只发送一轮，不检查四轴是否到位、不设置复位到位超时；指令下发后继续读取 YOLO 新结果，三个标靶重新稳定出现后恢复 PID。复位指令下发前的缓存画面不能用于重获确认。按 `Ctrl+C`（或收到 `SIGTERM`）结束时自动失能机械臂 ID1–4，然后关闭串口、网页和摄像头；清理期间再次按 `Ctrl+C` 不会中断失能流程。到达 `--duration` 的正常结束仍保留位置保持。支持 `python3 -m tasks.lock_target` 和从任意目录运行脚本绝对路径。

锁靶程序同时开启瞄准点矫正网页，默认监听 `0.0.0.0:8080`。本机访问 `http://127.0.0.1:8080`，同一局域网访问终端打印的地址；端口可用 `python3 tasks/lock_target.py --web-port 8081` 修改，监听地址用 `--web-host` 指定。`--port` 仍表示机械臂串口。网页和跟踪共用摄像头，预览在独立线程中最多以 15 Hz 编码，无需另外启动 `debug/camera_web.py`。

独立锁靶程序和任务表中的 `lock-target-left`、`lock-target-middle`、`lock-target-right` 开始控制前，自动将电机 ID1、ID4 的驱动器速度环 Ki 临时设为 `0.05`。瞄准完成、运行时长结束、超时、异常或按 `Ctrl+C` 取消时，保持当前角度后恢复为 `0.005`，再返回后续任务或关闭设备。切换使用不保存的 `0x15` 命令，检查写入应答确认生效；`0x14` 读取的是已保存参数，不能用于回读临时参数。恢复值与保存值相同时也实际发送恢复命令；其余驱动参数沿用保存值。部分启动失败时也恢复已经尝试切换的轴；恢复时各轴分别尝试，通信失败会报告错误，正常完成后恢复失败则停止后续任务。

网页点击画面设置黄色瞄准点，也可输入相对画面中心的横向、纵向像素偏移，或使用方向按钮按所选像素步长微调；向右、向下为正。PID 从下一个新帧开始根据“标靶中心 − 瞄准点”控制两轴，修改瞄准点时重置旧积分和微分；初次选靶仍按原来的位置或颜色规则进行，校正不会重新选靶。网页绿色框显示当前锁定标靶，“恢复画面中心”将瞄准点恢复到画面正中。

点击“保存校正”将瞄准点写入 `tasks/target_lock_aim.json`，下次启动自动读取；只调整而不保存则仅对本次运行生效。恢复中心后同样需要保存才能覆盖旧校正。文件使用归一化坐标，分辨率变化时保持相同的画面相对位置，不加入 Git；可用 `--aim-file 路径` 指定另一份校正文件。退出程序时同时关闭网页、摄像头和串口。

摄像头和角度调试也可在项目根目录直接运行脚本，或使用绝对路径从任意目录启动：

```bash
python3 debug/camera_web.py --port 8080
python3 debug/angles.py --hz 5
```

摄像头默认采集 1280×720；扫码任务临时切换到 1920×1080，成功、超时或取消后都恢复 720p。摄像头需要支持这两种分辨率。开启 YOLO 后，同一帧的所有已开启模型推理完成才更新网页，检测框、边界与原图对应；后端只保留最新完成帧，发送较慢时跳过中间帧。关闭全部模型或扫码期间显示实时原图。显示频率随推理、JPEG 编码和网络速度变化，没有固定刷新间隔。

点击“截图”会在运行摄像头程序的机器上保存 JPEG，默认目录为项目下的 `screenshots/`，网页显示完整保存路径。可在 `config.py` 的 `VISION['screenshot_dir']` 修改目录。截图目录不上传 Git。网页还支持模型独立开关与扫码。

角度调试每次启动时以当前四轴编码器位置重建软件零点，起始逻辑角为 `0 0 160 24`（由 `ARM['joint_offsets_deg']` 配置）。默认每行只打印六列角度，顺序为 `q1 q2 q3 q4 servo1 servo2`，单位为度，舵机保持绝对角度；缺失读数打印 `nan`。软件归零只建立逻辑基准，不移动机械臂。`--json` 保留完整反馈及单个设备错误详情。

测试使用模拟设备、假串口和假模型结果，不驱动实车；覆盖动作顺序、目标判断、二维码解码、反馈过期、碰撞检测、控制算法及异常清理。实机到位精度和 GPU 推理需要现场验证。
