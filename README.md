# 比赛小车

普通 Python 项目，从项目根目录直接运行，无需 ROS、colcon、安装自己的包或加载环境脚本。

先查看计划，不开串口、摄像头，也不发送运动命令：

```bash
python3 main.py --dry-run
```

干跑共用实际主线和路线函数，打印全部动作及参数。二维码用 `211` 演示颜色、形状映射；视觉分支只打印条件和已填写的中间小球动作，不选择实际位置。

在 `config.py` 设置电机、IMU、机械臂与夹爪串口、摄像头及推理设备，再运行比赛：

```bash
python3 main.py
```

电机与 IMU 端口留空会自动识别；机械臂沿用原稳定设备路径；夹爪留空沿用只读舵机识别及 `arm/servo_binding.json` 绑定。建议实机填写固定端口，避免自动识别探测其他设备。默认推理为 `cpu`，本机已有可用 CUDA 环境时可把 `VISION['infer_device']` 改成 `cuda:0`。

依赖见 `requirements.txt`。保留本机可用的 OpenCV、PyTorch、torchvision 和 CUDA，不自动更换这些库。设备按需连接，每条串口和摄像头整趟共用；编码器、IMU、摄像头后台采集，需要视觉行驶时启用后台边界推理。

## 改路线和动作

```text
car/
├── main.py             比赛主线
├── config.py           端口、控制参数、机械臂限位和模型路径
├── control.py          取消、等待和逐项清理
├── requirements.txt    运行依赖
├── README.md           运行与调试说明
├── tasks/              比赛任务
│   ├── route.py        路线
│   ├── scan.py         抬头扫码、解析、回位
│   ├── ball.py         小球观察与夹球动作
│   ├── target.py       打靶动作，待填写
│   └── delivery.py     取放物体动作，待填写
├── base/               底盘接口、算法及电机驱动
├── arm/                机械臂会话、驱动、校验、舵机绑定和许可证
├── vision/             摄像头、识别及直接反馈
│   └── models/         跑道与物体两套模型
├── sensor/             IMU 采集与逐帧碰撞检测
├── debug/              摄像头网页、角度调试和干跑设备
├── tests/              回归测试
│   ├── run.sh          测试脚本
│   └── fixtures/       固定动作基准
└── docs/               重构指南
```

想改路线打开 `tasks/route.py`，想改夹球打开 `tasks/ball.py`，想调参数打开 `config.py`，看 `main.py` 就能读懂比赛流程。原重构要求保存在 [docs/REFACTOR_GUIDE.md](docs/REFACTOR_GUIDE.md)。

原主线 25 步及中间小球 7 步的顺序、数值不变。距离 m、底盘速度 mm/s、角度度，步骤间隔仍为 0.5 秒。普通直走支持负距离，视觉直走仅接受正距离。

二维码必须是三位 `1..3`：第 1 位选球颜色，第 2 位选靶颜色（1 红、2 绿、3 蓝），第 3 位选物体形状（1 圆柱、2 圆锥、3 腰鼓）。球和物体复用 YOLO 权重，靶复用 HSV 识别；必须完整看到三个候选、目标唯一、连续稳定才返回左/中/右。无法确认会超时报错并停止主线。

机械臂校准只读取当前位置作为软件基准，不运动；初始逻辑角为 `0 0 160 24`，`home()` 回本次初始姿态。夹爪 ID2，张开 291°、闭合 243°，夹持不等待闭合到位，退出不自动松开物体。

编码器比例仍为 `0.00016029 m/count`；普通直走和视觉控制轮距 190 mm，圆弧轮距 0.41 m，圆弧原有 `6379 count/m` 换算也保留，没有重新标定。重复或过期反馈不能续期，编码器增量只消费一次；反馈/视觉丢失会停车。

`Ctrl+C` 会取消动作并逐项尝试停车、关闭设备。清理失败会打印原因，继续清理其他设备，并保留原始异常。

## 尚未填写

只有中间小球动作已实现。左/右小球、左/中/右靶、左/中/右物体共 8 个分支会抛出 `NotImplementedError`。打靶、取放物体的路线和观察姿态也待补充，尚未接入 `main.py`；填写实际动作后再启用。选中空小球分支会停止，不继续后续路线。

原任务表已删除，迁移时的主线 25 步和中间小球 7 步保存在 `tests/fixtures/mission_actions.json`，仅用于回归测试。比赛流程直接调用 Python 任务函数。

## 调试和验证

独立调试时不要同时运行比赛主线，避免争用串口或摄像头：

```bash
python3 -m debug.camera_web --port 8080
python3 -m debug.angles --hz 5
python3 -m debug.angles --hz 5 --duration 10 --json
```

摄像头程序打印局域网地址，网页支持实时画面、截图下载、边界/物体模型独立开关与扫码。关闭模型后摄像头继续采集。角度调试只读四轴电机和舵机 ID1、ID2，不校准、不使能、不发送运动命令；单个设备通信错误独立显示，不以零角度代替。

```bash
bash tests/run.sh -q
# 或
python3 -B -m unittest discover -s tests -t . -q
```

测试使用模拟设备和假串口，覆盖迁移顺序、目标判断、实际二维码解码、反馈过期、逐帧碰撞、控制算法、异常停车与逐项清理，不自动驱动实车。实机到位精度和目标 GPU 推理仍需现场验证。
